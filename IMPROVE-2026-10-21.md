## Top recommendations (ranked, with effort S/M/L)

1. **Signer-only + NWC at-rest migration (M)** — shared with the 0xPrivacy family: `useNWC.ts` stores `nostr+walletconnect://` strings (spend secrets) in plaintext localStorage (`nwc-connections`); nsec logins persist via Nostrify localStorage. For a *live/public-facing* nostr site (zaps, DMs), the fix from the 0xPrivacy IMPROVE doc applies verbatim: NIP-07/NIP-46-first login, session-only nsec behind an advanced toggle, NWC encrypted at rest or session-only, and key `connectionInfo` by wallet pubkey rather than secret string.
2. **Dep alignment (S–M)** — oldest stack in the family together with admin-dashboard: @getalby/sdk ^5.1.1 → 8.0.3 (M, breaking), vite ^8.0.3 → ≥8.0.16 / current 8.3.4 (S, dev-server CVEs), nostr-tools ^2.13.0 → 2.25.2 (S), react ^19.2.4 → 19.3.1 (S), zod ^4.3.6 → 4.6.5 (S).
3. **CI test gate (S)** — only the GitLab Pages template (1-minute timeout); no GitHub workflow runs `npm run test`. Add `pull_request` workflow with `npm ci && npm run test`; remove `npm i --silent` self-install from scripts so lockfile is authoritative.
4. **Scaffold de-duplication (M)** — same shared-hook drift problem as admin-dashboard; extract or sync the login/NWC/DM hooks from one canonical source so the storage fix lands once.
5. **NIP-17-first DMs (S)** — DM stack supports NIP-17 (`MESSAGE_PROTOCOL.NIP17`); for a site branded around privacy, default to NIP-17 gift-wrapped DMs and label NIP-04 legacy (its metadata leaks counterparties).
